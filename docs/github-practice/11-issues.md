# 记录可执行的 issue

一条 issue 应帮助未来的自己或合作者理解具体工作。

## 建议内容

- 当前行为：发生了什么。
- 期望行为：希望怎样变化。
- 复现步骤：在什么环境下如何触发。
- 完成标准：如何确认问题解决。

练习 issue 应在标题和正文说明练习用途，不伪装成实际用户反馈。避免重复创建相同问题。

## 练习

为自己的实际待办写一条 issue，完成后链接相应 PR。跨仓库引用时使用完整仓库名称或链接。

## 完成时核对

只有满足完成标准后才标记完成；取消、重复、暂不处理应如实说明。

参考：[创建 issue](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue)。
