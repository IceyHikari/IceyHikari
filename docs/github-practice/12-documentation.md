# 检查文档交付

文档能否帮助读者完成操作，比字数更重要。

## 检查顺序

1. 说明运行前需要什么，以及从哪个目录执行。
2. 命令中的占位符必须清楚标记。
3. 说明输入文件、输出位置和覆盖行为。
4. 核对相对链接和文件名大小写。
5. 区分示例、实际运行结果和未验证内容。
6. 阅读 GitHub 渲染结果，检查标题、列表与代码块。

## 练习

请第一次接触项目的人按 README 操作，记录卡住的步骤。没有实际做过时，不写“已通过新用户测试”。

## 完成时核对

代码块成对闭合；路径存在；链接有描述；安装来源明确；验证陈述与实际工作一致。

参考：[GitHub Markdown 基础](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)。
